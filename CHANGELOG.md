# Changelog

проект придерживается [Semantic Versioning](https://semver.org/lang/ru/).

## [2.0.4] - 2026-08-10

### Добавлено

- Новый API конфигурации на основе `Config` и функциональных опций
  (`New(...Option)`): `WithConsole`, `WithDB`, `WithDebug`, `WithInfo`,
  `WithWarn`, `WithLogDir`. Позволяет создавать несколько независимо
  настроенных `Application` в одном процессе.
- Метод `(*Application) Close()` — останавливает фоновую горутину записи
  в БД, дожидается её завершения, закрывает подготовленный запрос,
  соединение с SQLite и открытый файл логов.
- Метод `(*Application) Fatalf(format string, args ...any)` — логирует
  сообщение с уровнем Error, корректно освобождает ресурсы через
  `Close()` и только затем завершает процесс. Заменяет собой
  `app.Log.Fatalf`, который вызывает `os.Exit` в обход `defer`.
- Асинхронная батч-запись логов в SQLite через буферизованный канал и
  отдельную горутину-писатель вместо синхронной подготовки и выполнения
  `INSERT` на каждый вызов логгера.
- Ротация файла логов по календарным дням (`rotatingFileHandler`) —
  файл переоткрывается автоматически при смене даты.
- Индексы `idx_logs_timestamp` и `idx_logs_level` в таблице `logs` для
  ускорения последующих выборок.

### Исправлено

- `DBHandler.IsHandling` теперь реально учитывает настроенные уровни
  логирования. Ранее метод всегда возвращал `true`, из-за чего в БД
  писались все уровни независимо от `IsDebugMode` / `IsInfoMode` /
  `IsWarnMode`.
- Подготовленный SQL-запрос (`stmt`) теперь создаётся один раз при
  инициализации, а не на каждый вызов `writeLogToDB` — устранён лишний
  overhead на каждую запись лога.
- Ошибка инициализации логгера БД теперь возвращается вызывающему коду
  (`error`) в новом API вместо того, чтобы только печататься в stdout.
- Файл логов (при отключённых консоли и БД) больше не "залипает" на
  дате запуска процесса — имя файла обновляется при смене дня.

### Изменено

- Соединение с БД, подготовленный запрос и файл логов теперь являются
  полями `Application`, а не пакетными глобальными переменными — это
  устраняет состояние гонки при использовании нескольких логгеров в
  одном процессе и упрощает тестирование.

### Не изменено (обратная совместимость)

- Все функции и переменные первой версии пакета сохранены с прежними
  сигнатурами: `SetLogConsole`, `SetLogToDB`, `SetIsDebugMode`,
  `SetIsInfoMode`, `SetIsWarnMode`, `DBPath`, `SetupApplication()`.
  Существующий код, использующий этот API, продолжает работать без
  изменений.
- Поведение `SetupApplication()` при ошибках намеренно оставлено
  прежним: паника при ошибке создания/открытия файла логов, тихая
  печать в stdout и продолжение работы без БД при ошибке её
  инициализации.

### Известные ограничения

- В legacy-API (`SetupApplication()` и пакетные `Set*`-функции) нет
  возможности настроить директорию файлового логгера — для этого
  необходимо использовать новый API (`New(..., WithLogDir(...))`).
- Пакетные переменные legacy-API считываются один раз в момент вызова
  `SetupApplication()`; изменение их значений после создания
  `Application` не влияет на уже настроенный логгер.
