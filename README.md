# SLOGAVP - Расширенный логгер с поддержкой SQLite

## Описание

SLOGAVP - это библиотека логирования для Go, которая предоставляет
расширенные возможности ведения журналов с поддержкой записи в SQLite
базу данных, консоль и файл. Библиотека построена на основе пакета
[gookit/slog](https://github.com/gookit/slog) и предлагает гибкую
настройку форматирования и хранения логов.

## Основные возможности

- Гибкая настройка уровней логирования (Debug, Info, Warn, Error, Fatal)
- Параллельная запись логов в консоль и SQLite базу данных
- Асинхронная батч-запись в БД через фоновую горутину — вызовы логгера
  не блокируются на дисковом I/O
- Автоматическое создание структуры базы данных, индексов и директорий
- Ротация файла логов по дням (используется, когда отключены и консоль, и БД)
- Подробная информация о месте вызова (имя файла, номер строки, имя функции)
- Настраиваемый формат вывода логов с цветовой подсветкой уровня
- Корректное освобождение ресурсов через `Close()` (закрывает БД,
  дожидается фонового писателя, закрывает файл логов)
- Два способа настройки: современный API на основе `Option` и
  устаревший (legacy) API на основе пакетных переменных — для
  обратной совместимости со старым кодом

## Установка

```shell
go get github.com/Anatoly8853/slog-avp/v2
```

### Зависимости

- `github.com/gookit/slog` — базовый функционал логирования
- `github.com/mattn/go-sqlite3` — драйвер SQLite

## Быстрый старт (рекомендуемый API)

Начиная с v2.0.4 основной способ создания логгера — функция `New` с
функциональными опциями `Option`. Она возвращает `error` вместо паники
и не полагается на глобальное состояние пакета, поэтому безопасна для
использования в нескольких независимых экземплярах в одном процессе.

```go
package main

import (
	"fmt"
	"os"

	slogavp "github.com/Anatoly8853/slog-avp/v2"
)

func main() {
	app, err := slogavp.New(
		slogavp.WithConsole(true),
		slogavp.WithDB("log/logs.db"),
		slogavp.WithDebug(true),
	)
	if err != nil {
		fmt.Fprintf(os.Stderr, "не удалось настроить логгер: %v\n", err)
		os.Exit(1)
	}
	defer app.Close() // важно: освобождает БД, файл и фоновый писатель

	app.Log.Info("Приложение запущено")
	app.Log.Debug("Отладочное сообщение")
	app.Log.Error("Произошла ошибка")

	doSomething(app)
}

func doSomething(app *slogavp.Application) {
	app.Log.Info("Выполняется doSomething")
}
```

### Доступные опции

| Опция                    | Назначение                                                                                          |
|---------------------------|------------------------------------------------------------------------------------------------------|
| `WithConsole(bool)`       | включить/выключить вывод в консоль                                                                   |
| `WithDB(path string)`     | включить логирование в SQLite и задать путь к файлу базы                                             |
| `WithDebug(bool)`         | включить/выключить уровень Debug                                                                     |
| `WithInfo(bool)`          | включить/выключить уровень Info                                                                      |
| `WithWarn(bool)`          | включить/выключить уровень Warn                                                                      |
| `WithLogDir(dir string)`  | директория для файлового логгера (используется, если консоль и БД отключены; по умолчанию `"log"`)  |

По умолчанию (если опции не переданы): консоль включена, уровни
Debug/Info/Warn включены, логирование в БД выключено.

### Аварийное завершение: `app.Fatalf`

Стандартный `app.Log.Fatalf(...)` сам вызывает `os.Exit(1)`, из-за чего
все отложенные `defer` (включая `defer app.Close()`) пропускаются, и
ресурсы (БД, файл, недописанные логи в очереди) не освобождаются
корректно. Для аварийного завершения используйте `app.Fatalf` — он
логирует сообщение, закрывает ресурсы через `Close()` и только потом
завершает процесс:

```go
bot, err := tgbotapi.NewBotAPI(cfg.TGtoken)
if err != nil {
	app.Fatalf("Нет токена TELEGRAM_TOKEN: %v", err)
}
```

## Устаревший (legacy) API

Сохранён для обратной совместимости со старым кодом, написанным под
первую версию пакета. **Использовать в новом коде не рекомендуется** —
переменные читаются один раз в момент вызова `SetupApplication()`,
поэтому не подходит для нескольких независимых логгеров или горячей
переконфигурации; также при ошибке настройки файла логгер паникует, а
при ошибке БД — просто печатает сообщение в stdout и продолжает работу
без БД (как и в первой версии пакета).

```go
package main

import slogavp "github.com/Anatoly8853/slog-avp/v2"

func main() {
	// Включаем логирование в БД
	slogavp.SetLogToDB(true)

	// Отключаем запись в консоль; если включена запись в БД,
	// файловый логгер при этом не активируется
	slogavp.SetLogConsole(false)

	// slogavp.DBPath = "log/logs.db" // путь по умолчанию, можно не задавать

	app := slogavp.SetupApplication()
	defer app.Close() // рекомендуется добавить даже в legacy-коде

	app.Log.Info("Приложение запущено")
	app.Log.Debug("Отладочное сообщение")
	app.Log.Error("Произошла ошибка")

	doSomething(app)
}

func doSomething(app *slogavp.Application) {
	app.Log.Info("Выполняется doSomething")
}
```

### Функции конфигурации (legacy)

| Функция                | Назначение                                       |
|--------------------------|---------------------------------------------------|
| `SetLogConsole(bool)`    | включение/выключение вывода в консоль             |
| `SetLogToDB(bool)`       | включение/выключение записи в БД                  |
| `SetIsDebugMode(bool)`   | управление уровнем Debug                          |
| `SetIsInfoMode(bool)`    | управление уровнем Info                           |
| `SetIsWarnMode(bool)`    | управление уровнем Warn                           |
| `DBPath` (переменная)    | путь к файлу SQLite (по умолчанию `log/logs.db`)  |

> В legacy-API нет способа настроить директорию файлового логгера
> (`WithLogDir`) — для этого нужно перейти на `New(...Option)`.

## Структура логов в БД

Логи сохраняются в таблице следующей структуры:

```sql
CREATE TABLE logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp DATETIME,
    level VARCHAR(10),
    message TEXT,
    file_name TEXT,
    line_number INTEGER,
    function_name TEXT
);

CREATE INDEX idx_logs_timestamp ON logs(timestamp);
CREATE INDEX idx_logs_level ON logs(level);
```

Запись в БД выполняется асинхронно: вызов логгера кладёт запись во
внутренний буферизованный канал, а отдельная фоновая горутина
последовательно пишет их в SQLite. Это не блокирует код приложения на
дисковом I/O и избегает конкурентных писателей в SQLite. При вызове
`Close()` канал закрывается и метод дожидается, пока писатель
обработает все накопленные записи.

## Освобождение ресурсов

И `New(...)`, и `SetupApplication()` возвращают `*Application`,
владеющий ресурсами (соединение с БД, подготовленный запрос, файл
логов, фоновая горутина). Чтобы они закрылись корректно, всегда
вызывайте `Close()` при завершении работы приложения:

```go
app, err := slogavp.New(slogavp.WithDB("log/logs.db"))
if err != nil {
	// обработать ошибку
}
defer app.Close()
```

Без вызова `Close()` часть логов, ещё не записанных фоновым писателем
в БД, может быть потеряна при завершении процесса.

## Миграция со старых версий

Код, написанный под первую версию пакета, продолжает работать без
изменений — все функции (`SetLogConsole`, `SetLogToDB`,
`SetIsDebugMode`, `SetIsInfoMode`, `SetIsWarnMode`, `DBPath`,
`SetupApplication()`) сохранены с прежними сигнатурами. Единственное
отличие: раньше пакет не предоставлял способа освободить ресурсы —
теперь рекомендуется добавить `defer app.Close()` после создания
`Application`.

Функция `SetupLogger() *slog.Logger`, существовавшая в самых ранних
версиях как отдельная точка входа, в текущей версии не экспортируется
напрямую — логгер всегда создаётся вместе с `Application` через `New`
или `SetupApplication`.

Для нового кода рекомендуется сразу использовать `New(...Option)`.
